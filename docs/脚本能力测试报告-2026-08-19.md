## 被测范围

### SC0 · Rhai 接缝（`cmx-rule-feel/src/script.rs`）

脚本能力的共用内核，负责把 `serde_json::Value` 上下文桥进 Rhai、跑脚本、桥回。四载体全部复用此路径。

核心约束（均经测试验证）：
- **沙箱**：`max_operations=100,000`（CPU 闸门）、`max_call_levels=32`（递归深度）、字符串 / 数组 / 对象各有尺寸上限
- **确定性**：用操作数计数而非 wall-clock 超时，不引 `Instant`，保 wasm / 确定性友好
- **Don't-Panic**：Rhai 官方保证 + 本模块不 `unwrap`，一切错误以 `Result` 返回
- **数值 f64 归一**：Rhai 有独立 i64/f64，整数结果递归 normalize 为 f64（对齐 FEEL 算术，防 `Number(2) != Number(2.0)` 型破坏）

API 入口：`POST /script/eval`（对标 `/feel/expression`，供设计器调试用）

### SC1 · 决策图 Script 节点

`DecisionGraph` 中的 `"script"` 节点类型，在 `graph.rs` 的节点 `type` 分发处新增 `"script"=>` 分支。

关键行为：
- 以当前累积上下文（前序节点输出 merge）为变量，跑脚本，返回对象 merge 进上下文
- 脚本须返回 Rhai `#{…}` map；返回非对象时归因失败并记录
- `nodeKind` 保持 `"script"`（修正了旧的 `fail` helper 硬编码 `"graph"` 的误标问题）
- 脚本运行期错误仅该节点 failure，不影响其他节点
- 图 Script 节点语法错 → `save_draft` 落库前通过 `check_scripts` 拦截

### SC2 · 决策表脚本单元格

`=rhai:` 前缀（`RHAI_PREFIX` 常量）：输出格值以此前缀开头时走 Rhai 求值，无前缀走 FEEL（零回归）。通过 `eval_scripted` 分派 helper 的 sniff 逻辑实现，**一行 seam 换**（`eval_output` → `eval_scripted`）。

**关键设计约束**：判定侧（`inputEntries`）永远 FEEL，**脚本仅在输出侧**。这一约束保证：
- gap / overlap 完整性分析对决策表的判定域始终有效
- 脚本单元格的引入不影响设计器的「空隙 / 重叠」提示

### SC3 · 脚本函数库（`cmx_rule_script_function` 表）

可复用的 Rhai 函数，求值前注册进引擎，决策表 / 图 / 脚本决策皆可按名调用。

生命周期：草稿（编译校验）→ 发布（`version+1`）→ 三载体可调 → 删除。

CRUD 端点：

| 端点 | 方法 | 说明 |
|------|------|------|
| `/functions` | GET | 函数列表 |
| `/functions/draft` | POST | 存草稿（含编译校验，语法错带行号被拦） |
| `/functions/{name}` | GET | 函数详情 |
| `/functions/{name}/publish` | POST | 发布（version+1，注册为可用） |
| `/functions/{name}` | DELETE | 删除 |

注册机制：`thread_local CURRENT_FUNCS` + `with_functions(fns, 闭包)` RAII（设→跑→恢复），全程同步无 await，无跨请求泄漏，支持子决策嵌套。未发布函数不注册；删除后不可调用（无泄漏）。

### SC4 · 脚本决策（`DecisionBody::Script`）

`kind:"script"` 的顶层决策体，结构：`{"kind":"script","lang":"rhai","script":"…"}`。`lang` 默认 `"rhai"`。脚本须返回对象（map）作为决策输出。

完整性分析：脚本决策黑盒，`analyze_def` 显式返回「脚本决策为黑盒，不参与完整性分析」（非静默假 complete），确保 gap/overlap 提示诚实。

## 架构约束验证

### 判定侧 FEEL 保护（§9）

脚本能力**仅在输出侧**，判定侧 `inputEntries` 永远 FEEL。本次测试直接验证：在含 `=rhai:` 输出格的决策表上运行 `analyze`，gap/overlap 分析照常检出覆盖缺口（发现 2 个 gap），与纯 FEEL 决策表完全一致。这是超越 ZEN 的架构保障，确保「可解释性」和「完整性分析」不因脚本逃生舱而退化。

### 沙箱三闸门

| 闸门 | 触发场景 | 限额 | 实测结果 |
|------|----------|------|----------|
| `max_operations=100,000` | 死循环 | 10 万步 | 0.07s 被 kill，含行号归因 |
| `max_call_levels=32` | 深递归 | 32 层 | Stack overflow 错误，含行号 |
| `max_string_size=64 KiB` | 指数字符串增长 | 64 KiB | Length too large 错误，含行号 |

### 数值 f64 归一

Rhai 有独立 i64/f64，`1+1` 返回整数 `2` 而非 `2.0`。不归一则同一决策表里 FEEL 输出格（`2.0`）与脚本输出格（`2`）产生不等 JSON，破坏测试用例 expected 匹配。`normalize_numbers` 递归把整数 Number 转为 f64，本次测试 `1+1=2.0`、`items.len()=3.0` 均已验证。
