## 二、Bug 清单（供修复）

### 🟡 BUG-001：`string()` 对整数返回带 `.0` 的字符串（FEEL 规范偏差）

- **严重度**：中（影响输出格式正确性，DMN 兼容性）
- **现象**：`string(42)` → `"42.0"`，`string(100)` → `"100.0"`
- **期望**（DMN FEEL 规范）：整数应转为 `"42"`、`"100"`（无小数尾巴）
- **根因**：FEEL 引擎值模型用 `f64`（`cmx-rule-feel/src/expr.rs`），整数与浮点无区分，`string()`/`to_str` 直接格式化 f64 带 `.0`。**精确位置**：`expr.rs:533` `fn to_str` 的 `other => other.to_string()` 分支，对 `Value::Number(42.0)` 产出 `"42.0"`
- **复现**：
  ```bash
  curl -XPOST :8094/api/rules/v1/feel/expression -d '{"expression":"string(42)","context":{}}'
  # → {"result":"42.0"}
  ```
- **影响面**：任何用 `string()` 拼接整数生成编码/单号/展示文本的输出格；报表/单据编号场景会出现 `"42.0"` 这类异常值
- **修复方向**：`to_str`/`string()` 对整数值（`x == x.trunc()` 且在安全整数范围）格式化为无小数形式；或引入整数/小数区分的数值封装

### 🟡 BUG-002：字符串拼接中 `null` 被转成字面量 `"null"`（FEEL 规范偏差）

- **严重度**：中（静默产生脏数据）
- **现象**：`"x-" + missing`（missing 未定义 → null）→ `"x-null"`
- **期望**（DMN FEEL 规范）：与 null 的字符串拼接应产生 `null`（或报错），而非字面量 `"null"`
- **根因**：`+` 运算符对字符串重载拼接时，`to_str(null)` 返回 `"null"` 而非传播 null。**精确位置**：`expr.rs:533` `fn to_str` 的 `Value::Null => "null".into()` 分支
- **对比**：数值算术 `null * 2` → `null`（此项符合规范 ✅），仅字符串拼接分支不一致
- **复现**：
  ```bash
  curl -XPOST :8094/api/rules/v1/feel/expression -d '{"expression":"\"x-\" + missing","context":{}}'
  # → {"result":"x-null"}
  ```
- **影响面**：输出格拼接缺失变量时，得到含字面 `"null"` 的脏字符串而非可识别的空值，下游难以察觉
- **修复方向**：字符串拼接中任一操作数为 null → 结果 null（与算术传播一致）；或在拼接前显式要求 `string()` 转换

### 🟠 BUG-003：仿真台/设计器的「输入事实」表单只按输入列生成字段，遗漏仅在输出表达式引用的变量

- **严重度**：中高（前端功能缺口，影响可用性 —— 用户无法完整试算）
- **现象**：`credit_approval` 决策，输入列是 `score`/`region`，但输出格 `income * 5` 引用了 `income`。仿真台（`simulator.js`）的 facts 表单**只渲染 score/region 两个输入框**，没有 income，导致：
  - 用户求值 → `maxLimit: null`（因 income 无法输入 → `null * 5` = null）
  - 见 `/tmp/qa-fe-simulator.png`：输出 `{"tier":"A","maxLimit":null}`
- **根因**：`web/ui-native/rule/simulator.js:107-108` —— `const inputs = d.inputs || []; const fields = inputs.map(...)`，facts 字段仅从**输入列** `d.inputs` 派生，未扫描输出表达式/命中表达式中引用的额外变量
- **验证引擎无误**：直接 API 传 `income` → `{"tier":"A","maxLimit":50000}` 正确，纯属前端表单字段不全
- **复现**：CDP 挂载 simulator + qa_credit，填 score/region 求值 → maxLimit=null
- **影响面**：凡输出/条件表达式引用了非输入列变量的决策，都无法在仿真台/设计器里完整试算；这在"输入做判定、输出做计算"的常见模式里很普遍
- **修复方向**：
  1. facts 表单字段来源 = 输入列变量 ∪ 输出/条件表达式中提取的自由变量（需一个轻量变量提取器）
  2. 或提供一个「原始 JSON facts」文本框兜底，让用户直接补充任意字段
  3. 同样问题需检查 `designer.js` 的 fx 测试输入

## 四、稳健性/健壮性观察（非 bug，但值得记录）

1. **无崩溃**：全程 223 项测试 + 边界深挖（巨值 `1e24`、中文字符串、负数取模、越界 substring、深度递归、空输入、畸形 FEEL），rules-server 无一次 500 崩溃/panic，均优雅返回结果或结构化失败归因。
2. **失败归因质量高**：单元格出错精确定位"规则行 N + 输入列 X + 错误原因"，UNIQUE 重叠给出冲突行号 `[1,2]`，远超 ZEN 的黑盒报错。
3. **null 传播语义**：算术 `null*2→null` 符合 DMN；仅字符串拼接分支不一致（BUG-002）。
4. **数值 f64 模型的连锁影响**：所有整数显示为 `50000.0` 形态，`string()` 带 `.0`（BUG-001）。这是 R1 已知偏差（文档已披露），但 `string()` 场景值得优先修。
5. **seed 数据 `credit_approval` 有潜在 UNIQUE 重叠**：行1`[650..750)&north` 与 行2`[650..750)&-` 对 north 中分同时命中，U 策略下求值直接失败。**建议**：gap/overlap 分析本可提前发现（该表 analyze 应报 overlap），演示数据应改用 `A`/`P`/`F` 策略或收紧区间。

## 五、修复优先级建议

| 优先级 | Bug | 理由 |
|--------|-----|------|
| P1 | BUG-003 仿真表单字段不全 | 直接影响用户能否完整试算，可用性缺口最大 |
| P2 | BUG-001 string(整数)带.0 | 影响编号/文本输出正确性，DMN 兼容性 |
| P3 | BUG-002 拼接 null→"null" | 静默脏数据，但触发条件较窄（缺失变量拼接）|

三者都不阻断核心求值。BUG-001/002 同源于 f64 数值模型，可一并考虑引入整数/小数区分或 Decimal 迁移（R2+ 规划）。
